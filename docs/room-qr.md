# QR ประจำห้องและการเข้าใช้นอกคลาส

## ผู้ใช้งาน

- อาจารย์/ผู้ดูแล: ห้องปฏิบัติการ → QR หน้าห้อง / พิมพ์ → PNG หรือพิมพ์/PDF
- ผู้ใช้ห้อง: สแกนป้ายเดิม ตรวจชื่อห้อง แล้วลงชื่อของตนเอง
- ผู้ดูแลระบบ: รายงาน → การเข้าใช้นอกคลาส เพื่อค้นหา ส่งออก และปิดรายการค้างพร้อมเหตุผล

QR ใช้ `rooms.qr_token` เดิม ผ่าน GitHub Pages gateway `?page=room-checkin&token=...` ไม่ผูกกับ URL tunnel ชั่วคราว จึงไม่ต้องพิมพ์ใหม่เมื่อเปลี่ยนคลาสหรือ tunnel ตราบใดที่ยังเป็นฐานข้อมูลและ gateway เดิม การเปิดออนไลน์ยังต้องให้ Docker/เครื่องและ tunnel ทำงานอยู่

## การเลือกแบบฟอร์ม

1. ห้องงดใช้งาน: ไม่รับรายการใหม่ แต่ใบยืนยันเดิมยังกดออกได้
2. ช่วงก่อนเรียน 10 นาทีถึงเวลาสิ้นสุด: แสดงคลาสที่ตรงห้องและเวลา ให้เลือกคลาสเอง ไม่เดาว่าเข้าเรียนคลาสใด
3. คลาสปิดรับ/ยังไม่เปิด: แจ้งให้ติดต่อผู้สอน ไม่ใช้การลงชื่อนอกคลาสข้ามการปิดรับ
4. มีแผนรายสัปดาห์เก่าที่ยังไม่สร้างคลาส: ให้ติดต่อผู้สอน
5. ไม่มีคลาสในช่วงนั้น: ลงชื่อรหัส ชื่อ ประเภท และวัตถุประสงค์ เวลาเข้าบันทึกจากเซิร์ฟเวอร์ โดยไม่สร้างคลาสหรือบัญชีปลอม
6. ใช้เสร็จ: กดออกจากห้อง หรือสแกนป้ายเดิมด้วยเบราว์เซอร์เดิม

QR รายคลาสที่เคยแจกยังใช้ได้ และยังใช้ส่งลิงก์ตรงในกรณีผู้สอนเปิดรับเพิ่มเติมนอกตารางได้ แต่ป้ายหน้าห้องให้ใช้ QR ประจำห้อง

## ความถูกต้องและความเป็นส่วนตัว

- เก็บข้อมูลนอกคลาสใน `room_visits` แยกจาก `attendance_records` ไม่เปลี่ยนข้อมูลคลาสเดิม
- ตรวจห้อง/คลาส/ความจุซ้ำภายใน transaction ก่อนบันทึก ป้องกันฟอร์มเก่าและคำขอพร้อมกัน
- รหัสหนึ่งมีรายการนอกคลาสที่ยังไม่กดออกได้หนึ่งรายการ ป้องกันกดซ้ำด้วย request ID และ unique constraint
- QR เป็นลิงก์สาธารณะ ไม่ใช่หลักฐานยืนยันตัวตนหรือการอยู่หน้าห้อง และการลงชื่อไม่ใช่การอนุมัติเข้าใช้ห้อง ข้อมูลเป็นการแจ้งด้วยตนเอง
- บุคคลทั่วไปเห็นเฉพาะใบยืนยันของตนเอง ไม่มีรายชื่อห้องสาธารณะ ผู้ดูแลระบบเท่านั้นดู/ปิดรายการนอกคลาสได้ สิทธิ์ข้อมูลคลาสของอาจารย์คงเดิม
- ใบยืนยันเก็บเป็นค่าลับสุ่มในคุกกี้ HttpOnly/SameSite และ Secure เมื่อออนไลน์ อายุ 7 วัน ไม่มีชื่อหรือรหัสผู้ใช้ในคุกกี้ ในฐานข้อมูลเก็บเพียง hash ค่าใบยืนยัน หากล้างคุกกี้ เปลี่ยนเบราว์เซอร์ หรือ tunnel เปลี่ยนโดเมน ให้ติดต่อผู้ดูแลเพื่อปิดรายการค้าง
- ไม่ปิดรายการอัตโนมัติด้วยเวลาสมมติ การปิดโดยผู้ดูแลต้องมีเหตุผลและ audit log

## รายงาน

เลือกตามวันที่/เวลา **เข้า** ห้อง สถานะ คำค้น และลำดับเดียวกันทั้งหน้าจอ CSV และฉบับพิมพ์ ส่งออกทั้งหมดที่ตรงตัวกรอง ไม่ใช่เฉพาะหน้า 50 รายการที่กำลังแสดง

ระยะเวลารายบุคคลคำนวณทั้งรายการเมื่อผู้ใช้กดออกเองเท่านั้น แสดงเป็นชั่วโมงหรือคาบ 50/60/90 นาทีได้ รายการค้างหรือที่ผู้ดูแลปิดแสดง “ไม่ทราบ” ไม่รวมเวลาของหลายคนเป็นชั่วโมงใช้ห้อง และไม่บวกกับชั่วโมงตามตารางเรียน CSV ป้องกันสูตรจากข้อมูลที่ผู้ใช้กรอก

## ตรวจสอบก่อนเผยแพร่

`tests/room-visits-regression.php`, `tests/room-visits-concurrency.php`, `tests/room-visits-http.php` และ `tests/gateway.test.mjs` ครอบคลุมการลงชื่อ/ออก คำขอซ้ำ ความจุ สิทธิ์ รายงาน สถานะคลาส คุกกี้ใบยืนยัน และการเปลี่ยน tunnel โดยใช้ฐานข้อมูลทดสอบแยกเท่านั้น

การเพิ่มตารางเป็น additive migration ต้องสำรองฐานข้อมูลจริงก่อนอัปเดต ตรวจว่า room token/คลาส/การลงชื่อเดิมคงเดิมหลังเริ่ม container ใหม่ และอย่าลบ production volume
