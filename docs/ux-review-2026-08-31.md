# UX review — 31 August 2026

## Scope and priorities

Lecturers and administrators need to find a class, understand its current attendance status, inspect its QR and review attendance quickly. Students need a truthful check-in result and a recovery action when a class has not started.

The existing Thai-first navy/teal design and workflows were retained. The class list is the primary workspace; its create action remains in the top bar. Empty search results are distinguished from a system with no records, submission feedback describes the current action, invalid fields receive focus, and success requires a saved result.

## Changes

- Fixed weekday/weekend switching and retained search text when changing weeks or selecting a timetable entry.
- Timetable result count now describes only entries visible in the chosen week and day range, with an empty-result explanation.
- Class filters match displayed statuses: waiting, accepting attendance and expired are separate.
- The dashboard's expired-class summary links directly to the matching class list.
- Class tables use full available width on typical desktop/tablet screens; the form moves beside them only on wide screens. Actions no longer require horizontal scrolling at 1440px or 768px.
- Corrected mobile table field alignment, report attendance units, datetime input sizing and tablet dashboard overflow.
- Added clear-filter actions and contextual no-match states for classes and attendance history.
- Minimum control targets are 44px; anchor destinations clear the sticky header.
- Student success screens require a matching session receipt, show the submitted student code and distinguish duplicate attendance. Waiting classes have a retry link, and cancelled future classes no longer appear to be awaiting opening.
- Added isolated regression coverage to Container CI and made PHP lint failures propagate to the CI step.

## Verification

- PHP 8.2 syntax check: all repository PHP files passed.
- `node --check assets/app.js`: passed.
- `php tests/ux-regression.php`: 30 assertions passed. Tests use an in-memory SQLite database by default, never the application's database.
- `git diff --check`: passed. No formatter/type-check configuration is present in this plain PHP repository.
- Browser inspected at 1440px, 768px and 390px. Dashboard, classes, timetable, records, rooms and reports had no document-level horizontal overflow after fixes. Wide timetable scrolling remains intentional.
- Checked status filter results, dashboard drill-down, 5/7-day toggles, search preservation, empty search states, keyboard focus, invalid form handling, close-class confirmation/cancel, student success, duplicate submission, waiting and cancelled class states.
- No JavaScript warning/error logs were recorded in the inspected test tab.

## Limits and environment

Testing used XAMPP PHP 8.2 on loopback port 8087 with newly generated synthetic data and separate temporary sessions. The existing Docker database and volumes were not changed. Docker Desktop was not running; the earlier local rebuild had been blocked by approval review, so the updated container was not tested locally.

Real-device QR camera permissions, unstable-network recovery and a production-hosted website were not tested in this review. Render deployment and a verified production URL remain separate prerequisites; a Render Blueprint in Git is not proof of a running service.

To launch the updated Docker app, start Docker Desktop, open a terminal in this project and run `docker compose up --build -d`, then open `http://localhost:8086`. Use `docker compose stop` to stop it without removing stored data.
